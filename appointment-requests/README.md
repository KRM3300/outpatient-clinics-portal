# نظام طلبات مواعيد العيادات الخارجية
## حالة الإصدار
**تطوير تجريبي غير منشور**. لا تستخدم بيانات مرضى حقيقية. لا يوجد ربط حالي بجدول الأطباء أو نظام المواعيد أو خدمة إرسال رسائل.
## الخدمات
- موعد إضافي لمرضى الطوارئ: رقم الملف أو الهوية + اسم المراجع + العيادة + الطبيب + تاريخ العيادة + فترة ذات وقت مقترح (10:30، 14:30، 18:30).
- موعد متابعة: الحقول نفسها مع الفترة، ويُبلغ المريض أن رسالة ستصله **بعد تأكيد الحجز**، ولا يحتاج لمراجعة الاستقبال لغرض الحجز.
- الواجهات بالعربية والإنجليزية. البيانات التجريبية تحفظ محليًا في المتصفح، ولا تنتقل إلى Supabase.
## الأدوار المستهدفة
- doctor / nurse: رفع طلب بعد الاعتماد.
- scheduler: معالجة الطلب والحجز وتوثيق المرجع.
- supervisor: متابعة الطلبات المتأخرة.
- admin: اعتماد حسابات الموظفين وتوزيع الصلاحيات، ومراقبة النظام.
## دورة الطلب
pending → processing → booked أو unable. لا تُعد حالة booked دليلًا على حجز فعلي إلا بعد التحقق من نظام المواعيد. إرسال الرسالة حالة مستقلة (not_sent / sent / failed).
## متطلبات تفعيل Supabase
1. التحقق من قاعدة البيانات الحالية والنسخ الاحتياطية قبل تنفيذ schema-review.sql؛ الملف **مقترح للمراجعة فقط** وليس migration منفذًا.
2. اعتماد إدارة المستشفى وأمن المعلومات ومراجعة تصنيف البيانات وموقع الاستضافة والتعاقد مع الموردين.
3. تصميم مسار تسجيل أولي آمن لا يسمح للمستخدم باختيار الدور أو حالة الاعتماد. يجب أن ينشئ المستخدم حسابًا pending فقط؛ اعتماد الدور عبر مسار إداري محمي، وليس من المتصفح مباشرة.
4. إنشاء حساب admin أولي بإجراء إداري موثوق، مع تسجيل عمليات الاعتماد والرفض والتعليق.
5. إعداد Auth Email OTP بتعديل قالب Magic Link إلى {{ .Token }} وإعداد مزود SMTP مناسب؛ مع تحديد حدود إعادة الإرسال.
6. إعداد سياسات RLS لكل جدول، والاختبار بحسابات غير معتمدة ومعلقة ومرفوضة، وليس بحساب admin فقط.
7. إنشاء واجهة معالجة الطلبات وتغيير الحالات عبر واجهة خادم آمنة، والتحقق من مصدر جدول الأطباء وتاريخ ووقت العيادة.
8. تفعيل الرسائل فقط عبر قناة رسمية معتمدة وتوثيق نتيجة الإرسال؛ لا نعد المريض بإشعار مضمون ما لم يكن المسار يعمل.
9. اختبار 20/40/60 مستخدمًا متزامنًا من الجوال وشبكة المستشفى، ومراقبة الاستعلامات والتخزين.
## قائمة قبول النشر
- [ ] لا يمكن للمستخدم غير المعتمد قراءة أي طلب.
- [ ] لا يمكن للمستخدم تغيير دوره أو اعتماد نفسه.
- [ ] لا يمكن لطبيب تأكيد الحجز بنفسه.
- [ ] لا يمكن عرض تاريخ عيادة غير موجود في الجدول المعتمد.
- [ ] منع الطلبات المكررة أو تنبيه المستخدم عنها.
- [ ] توثيق جميع تغييرات الحالة وهوية المنفذ.
- [ ] تدقيق إتاحة الواجهات واللغة والتجاوب.
- [ ] اختبار إرسال الرسائل وحالات الفشل.
- [ ] موافقة مالك الخدمة وأمن المعلومات قبل استخدام بيانات حقيقية.
